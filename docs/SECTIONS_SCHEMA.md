# `app/data/sections.json` 스키마

`tools/build_catalog.py`가 「제6기(2027~2030) 지역사회보장계획 수립 안내 [시·군·구]」
원본 hwpx에서 기계 추출해 만든다. 사람이 손으로 고치지 않는다(고칠 일이 생기면
`tools/catalog_overrides.json`에 적고 빌더가 덮어쓰게 한다).

```jsonc
{
  "source": "제6기(2027~2030) 지역사회보장계획 수립 안내 [시·군·구]",
  "scope": "시군구",
  "generated_at": "2026-09-08T00:00:00",
  "template": "template.hwpx",
  "body_section": "Contents/section2.xml",
  "stats": { "chapters": 5, "nodes": 42, "forms": 65, "howtos": 16 },

  "nodes": [
    {
      "id": "01",                         // 안정 식별자. 화면·산출 파일명에 쓴다
      "depth": 0,                         // 0=장 1=절 2=항 3=목
      "no": "01",                         // 원문 번호 표기 그대로
      "title": "제6기 지역사회보장계획 정책 방향 및 체계",
      "page": 76,                         // 안내서 목차 쪽번호. 없으면 null
      "parent": null,
      "children": ["01-가", "01-나", "01-다"],

      "howto": {                          // 「◆ 작성 취지 및 방법 ◆」 박스. 없으면 null
        "purpose": "…작성취지 원문…",
        "method": "…작성방법 원문…",
        "raw": "…박스 전문…",
        "chars": 2013
      },

      "forms": [                          // 이 마디에 딸린 표
        {
          "idx": 0,
          "kind": "blank",                // blank=빈 양식 / example=작성례 / note=참조박스 / howto=지시문박스
          "rows": 6, "cols": 5,
          "header": ["성과지표 명 (단위)", "", "지표정의", "", "연도별 목표"],
          "grid": [["…"]],                // 행×열 문자열. 빈 양식이면 대부분 ""
          "colWidths": [22, 28, 20, 20, 10],   // 원본 셀 너비 비율(%). 합 100
          "required": true                // 절 산출 시 반드시 들어가야 하는 표인가
        }
      ],

      "limits": [                         // 지시문에서 추출한 수량 제약
        { "text": "추진전략(5개 이내)", "scope": "추진전략", "op": "max", "n": 5, "unit": "개" }
      ],

      "fixed": false,                     // true면 안내서가 "수정 불가"로 못박은 마디
      "markers": ["○", "▪", "-"]          // 이 마디 본문에서 실제로 쓰인 마커(작성 지침 참고용)
    }
  ]
}
```

## 규칙

- `id`는 상위 마디 id + `-` + 번호 표기의 앞 글자. 예 `01`, `01-가`, `01-가-1`, `03-나-1-(1)`
  - 번호 표기에서 괄호·마침표는 그대로 두되 파일명에 쓸 수 없는 문자(`/ \ : * ? " < > |`)는 `_`로 바꾼다
- 같은 제목이 두 번 나오면 뒤엣것에 `#2`를 붙인다(안내서에 실제로 중복 있음)
- `kind` 판정
  - `howto` — 셀에 `◆ 작성 취지 및 방법 ◆`가 있는 3×3 표
  - `note` — 1×1 표이면서 셀이 `※ (참조)`로 시작
  - `example` — 데이터 셀의 60% 이상이 비어 있지 않고, 같은 `rows×cols` 표가 바로 앞에 또 있는 경우의 **뒤엣것**
  - `blank` — 그 외. 같은 골격이 두 번 나오면 **앞엣것**이 blank
- `required`는 `kind === 'blank'`인 표 전부 참
- `limits` 추출 정규식은 `(?P<scope>[가-힣·\s]{2,20})\s*\(?\s*(?P<n>\d+)\s*(?P<unit>개|건|명)\s*(?P<op>이내|이상|이하)\)?`
  - `이내`·`이하` → `op: "max"`, `이상` → `op: "min"`
  - `5개 이상 8개 이내`처럼 범위면 두 항목으로 나눈다
- 지시문 `purpose`/`method` 분리 기준: 본문에서 `작성취지` / `작성방법` 라벨이 나오는 지점.
  라벨이 없으면 전문을 `raw`에만 담고 두 필드는 `null`
