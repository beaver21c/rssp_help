# `app/data/sections.json` 스키마

`tools/build_catalog.py`가 「제6기(2027~2030) 지역사회보장계획 수립 안내 [시·군·구]」
원본 hwpx에서 기계 추출해 만든다. 사람이 손으로 고치지 않는다(고칠 일이 생기면
`tools/catalog_overrides.json`에 적고 빌더가 덮어쓰게 한다).

```jsonc
{
  "source": "제6기(2027~2030) 지역사회보장계획 수립 안내 [시·군·구]",
  "scope": "시군구",
  "generated_at": "2026-09-08T00:00:00",
  "template": "template.hwpx",
  "body_section": "Contents/section2.xml",
  "stats": { "chapters": 5, "nodes": 42, "forms": 65, "howtos": 16 },

  "nodes": [
    {
      "id": "01",                         // 안정 식별자. 화면·산출 파일명에 쓴다
      "depth": 0,                         // 0=장 1=절 2=항 3=목
      "no": "01",                         // 원문 번호 표기 그대로
      "title": "제6기 지역사회보장계획 정책 방향 및 체계",
      "page": 76,                         // 안내서 목차 쪽번호. 없으면 null
      "parent": null,
      "children": ["01-가", "01-나", "01-다"],

      "howto": {                          // 「◆ 작성 취지 및 방법 ◆」 박스. 없으면 null
        "purpose": "…작성취지 원문…",
        "method": "…작성방법 원문…",
        "raw": "…박스 전문…",
        "chars": 2013
      },
      "howto_ref": null,                  // howto가 없을 때 기댈 마디 id (아래 규칙)
      "mirrors": null,                    // 1번 구조를 되풀이하는 마디면 1번 마디 id

      "forms": [                          // 이 마디에 딸린 표
        {
          "idx": 0,
          "seq": 12,                      // 본문에 나온 차례(도식 원본을 되찾는 열쇠)
          "kind": "blank",                // blank=빈 양식 / example=작성례 / layout=칸을 병합해 그린 체계도
                                          // note=참조박스 / howto=지시문박스
          "xml": null,                    // layout일 때만. 원본 문단 XML 파일(data/ 기준 상대경로)
          "rows": 6, "cols": 5,
          "header": ["성과지표 명 (단위)", "", "지표정의", "", "연도별 목표"],
          "grid": [["…"]],                // 행×열 문자열. 빈 양식이면 대부분 ""
          "colWidths": [22, 28, 20, 20, 10],   // 원본 셀 너비 비율(%). 합 100
          "required": true                // 절 산출 시 반드시 들어가야 하는 표인가
        }
      ],

      "limits": [                         // 지시문에서 추출한 수량 제약
        { "text": "추진전략(5개 이내)", "scope": "추진전략", "op": "max", "n": 5, "unit": "개" }
      ],

      "fixed": false,                     // true면 안내서가 "수정 불가"로 못박은 마디
      "markers": ["○", "▪", "-"]          // 이 마디 본문에서 실제로 쓰인 마커(작성 지침 참고용)
    }
  ]
}
```

## 규칙

- `id`는 상위 마디 id + `-` + 번호 표기의 앞 글자. 예 `01`, `01-가`, `01-가-1`, `03-나-1-(1)`
  - 번호 표기에서 괄호·마침표는 그대로 두되 파일명에 쓸 수 없는 문자(`/ \ : * ? " < > |`)는 `_`로 바꾼다
- 같은 제목이 두 번 나오면 뒤엣것에 `#2`를 붙인다(안내서에 실제로 중복 있음)
- `kind` 판정 (순서대로 본다)
  - `howto` — 셀에 `◆ 작성 취지 및 방법 ◆`가 있는 3×3 표
  - `note` — 1×1 표이면서 셀이 `※ (참조)`로 시작
  - `example` — 같은 `rows×cols` 표가 바로 앞에 또 있으면서 채움률 60% 이상인 **뒤엣것**,
    또는 머리행을 뺀 데이터 칸의 55% 이상이 이미 차 있는 표
  - `layout` — 머리행이 통째로 빈 표. 전략체계도처럼 **칸을 잘게 나눠 병합하고 칸마다
    테두리를 달리 준 체계도**라 파이프 표로 받아쓸 수 없다(27×29, 16×15 두 건).
    작성용 양식에서 빼는 대신 원본 문단 XML을 `app/data/layout/<id>-<idx>.xml`로 떼어
    두고 `xml`에 경로를 적는다. 산출할 때 자리표 `[[도식:<id>#<idx>]]`를 그 문단으로
    갈아 끼우면 칸 병합·테두리·글꼴이 원본 그대로 살아난다
    (배포용 `template.hwpx`의 `header.xml`이 안내서 원본과 바이트가 같아서 가능하다)
  - `blank` — 그 외
- `required`는 `kind === 'blank'`인 표만 참
- `limits`는 숫자·단위·연산자를 정규식 `(\d+)\s*(개|건|명)\s*(이내|이상|이하)`로 잡고,
  **대상은 숫자 앞 40자에서 아래 목록 가운데 가장 가까운 말을 고른다.**
  목록에 없으면 그 제약은 버린다 — 아무 한글이나 되짚으면 `있는 5개`, `반올림함 2개`처럼
  검사에 쓸 수 없는 토막이 나온다.
  - 대상 목록: 추진전략 / 사회보장 전략 / 균형발전 전략 / 중점추진사업 / 세부사업 /
    대표과업 / 세부과업 / 성과지표 / 주요 계획 / 전략과제 / 핵심과제 / 전략
  - `이내`·`이하` → `op: "max"`, `이상` → `op: "min"`
  - `5개 이상 8개 이내`처럼 범위면 두 항목으로 나눈다
- 지시문 `purpose`/`method` 분리 기준: 본문에서 `작성취지` / `작성방법` 라벨이 나오는 지점.
  라벨이 없으면 전문을 `raw`에만 담고 두 필드는 `null`
- `howto_ref` — 65개 마디 중 지침 박스를 직접 가진 것은 16개뿐이다. 나머지는
  ① 조상 → ② 자손(문서 순서로 첫 번째) → ③ 같은 장 안에서 가장 가까운 마디 순으로 찾아
  그 마디 id를 적는다. 글월을 복사하지는 않는다
- `mirrors` — 안내서는 `[사회보장 전략 1]`만 펼쳐 적고 2~4는 제목만 둔다. 2~4번 마디에
  1번 마디 id를 적어 두어 화면이 같은 표 양식·지침을 쓰게 한다
